# AI Auto Service

Վարորդը chat-ում նկարագրում է մեքենայի խնդիրը, AI-ը գտնում է ծառայությունը և գարաժները (գնով, ժամերով), իսկ վարորդը կարող է թողնել հայտ։ Գարաժների, գների, ժամերի և հայտերի կառավարումը՝ ադմին պանելում։

## Ֆայլեր

| Ֆայլ | Դերը |
|---|---|
| `data.py` | մոդելներ + նմուշային տվյալներ |
| `db.py` | SQLite բազա (աղյուսակներ, seed, `python db.py ...`) |
| `queries.py` | ընթերցում/գրառում բազայում |
| `api.py` | FastAPI. հանրային endpoint-ներ, `/app`, `/panel` |
| `admin.py`, `auth.py` | ադմինի API (դերերով), մուտք, rate limit |
| `telegram.py` | Telegram ծանուցումներ և կապ (webhook) |
| `pwa.py` | տեղադրվող հավելված. manifest, պատկերակներ, service worker |
| `chat.py` | AI (Claude + գործիքներ) և պարզ ռեժիմ |
| `chat.html`, `review.html`, `admin.html` | վարորդի chat-ը (քարտեր), վարորդի գնահատման էջը, ադմին պանելը |
| `test_api.py` | API-ի, բազայի, ադմինի, հայտերի թեստեր՝ `python test_api.py` |
| `test_ai.py` | AI-ի հանգույցի թեստ կեղծ սերվերով (բանալի պետք չէ)՝ `python test_ai.py` |
| `test_telegram_browser.py` | Telegram-ի կապի և ծանուցումների դիտարկչային թեստ (կեղծ Telegram API-ով)՝ `python test_telegram_browser.py` |
| `test_browser.py` | իրական դիտարկչով թեստ (`pip install playwright && playwright install chromium`)՝ `python test_browser.py` |

## Գործարկում ձեր համակարգչում

```
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # ցանկության դեպքում. առանց սրա chat-ը պարզ ռեժիմում է
uvicorn api:app --reload
```

- Chat՝ http://127.0.0.1:8000/app
- Ադմին՝ http://127.0.0.1:8000/panel (dev-ում գաղտնաբառը `admin`, եթե `ADMIN_PASSWORD` չեք նշել)
- API-ի փաստաթղթեր՝ http://127.0.0.1:8000/docs

## Դերեր. ինչպես է յուրաքանչյուր գարաժը տեսնում միայն իր հայտերը

- **Գլխավոր ադմին** (`ADMIN_PASSWORD`). մուտքանունը թողնում է դատարկ։ Տեսնում և կառավարում է ամեն ինչ։
- **Գարաժի սեփականատեր.** գլխավոր ադմինը «Գարաժներ» → գարաժ → «Գարաժի մուտք» բաժնում սահմանում է մուտքանուն և գաղտնաբառ։ Սեփականատերը մտնում է նույն `/panel` էջով և տեսնում է **միայն իր** հայտերը, գները, ժամերը. նա չի կարող դիպչել այլ գարաժին, կատալոգին կամ ջնջել գարաժ։
- **Հայտի ուղղորդում.** եթե վարորդը հայտի ձևում ընտրել է գարաժ, հայտը գնում է հենց այդ գարաժին։ Առանց ընտրության հայտերը տեսնում է միայն գլխավոր ադմինը և նշանակում է գարաժի («Հայտեր» էջում)։

## Հայտի փուլեր և հաշվետվություն

Յուրաքանչյուր հայտ ունի փուլ, որը գարաժը թարմացնում է «Հայտեր» էջում.
**Նոր → Զանգահարվել է → (Չպատասխանեց) → Ժամ պայմանավորվեց → Այցելեց**, կամ **Հրաժարվեց** (պարտադիր պատճառով՝ թանկ է, հեռու է, գնաց այլ գարաժ, ժամը չհամապատասխանեց, այլևս պետք չէ, այլ)։

«Հաշվետվություն» էջը (ամսական, Երևանի ժամանակով) ցույց է տալիս.
- քանի հայտ եկավ, քանի տոկոսի հետ կապվեցին (**Արձագանքվել է**), քանիսի հետ ժամ պայմանավորվեցին, քանիսն **այցելեցին**,
- **արձագանքման միջնային ժամանակը** (հայտի ստեղծումից մինչև առաջին փուլի փոփոխությունը),
- հրաժարումների պատճառները։

Ադմինը տեսնում է բոլոր գարաժները և «Նշանակված չէ» հայտերը, գարաժը՝ միայն իրենը։

**Սահմանափակումներ.** վիճակները **ընթացիկն են** (պատմություն չենք պահում), ուստի «ժամ պայմանավորվեց»-ի տոկոսը հաշվում է հիմա «ժամ»/«այցելեց» փուլում գտնվողներին։ «Այցելեց» փուլը լրացնում է հենց գարաժը, և դուք չեք կարող ստուգել դրա ճշտությունը (հաճախորդի հաստատում դեռ չկա)։ Արձագանքման ժամանակը ճշգրիտ է միայն գարաժի պանելը օգտագործելու դեպքում։

## Հավելված հեռախոսում (PWA)

Կայքը կարելի է **տեղադրել որպես հավելված**. պատկերակը հայտնվում է հեռախոսի գլխավոր էկրանին, բացվում է ամբողջ էկրանով, առանց բրաուզերի հասցեագոտու։ Երկու առանձին հավելված կա՝ **վարորդի** (`/app`) և **գարաժի պանելի** (`/panel`)։

- **Android (Chrome).** բացեք էջը → վերևում կհայտնվի **«Տեղադրել հավելվածը»** կոճակը (կամ Chrome-ի մենյու ⋮ → *Install app* / *Add to Home screen*)։
- **iPhone (Safari).** բացեք էջը → **Share** (քառակուսի սլաքով) → **Add to Home Screen**։ Chat-ը ինքն է ցույց տալիս այդ հուշումը։
- **Համակարգիչ (Chrome/Edge).** հասցեագոտու աջ կողմում կհայտնվի տեղադրման պատկերակ։

Պահանջվում է **HTTPS** (Render-ը տալիս է ավտոմատ)։ Պատկերակը ժամանակավոր է. փոխարինելու համար վերցրեք `pwa.py`-ի `ICONS_B64`-ը ձեր լոգոյի PNG-ներով (192, 512, maskable 512, apple-touch 180)։

**Offline.** նախկինում բացված էջերը բացվում են առանց կապի, բայց տվյալներ (չատ, հայտեր) առանց ինտերնետի չեն աշխատում. կերևա «Կապ չկա»։ Service worker-ը քեշավորում է **միայն** `/app` և `/panel` էջերի «կեղևը», երբեք՝ API-ի պատասխանները կամ գաղտնի գնահատման հղումները։

**Սա store հավելված չէ.** այն չի գտնվում App Store-ում կամ Google Play-ում, և **push ծանուցումներ չունի** (ծանուցումների համար օգտագործվում է Telegram)։

## Գարաժի քարտեր և գնահատականներ

**Chat-ում** գարաժները երևում են քարտերով՝ գին, հասցե, բաց է/փակ է, **գնահատական** և **«Թողնել հայտ»** կոճակ։ Կոճակը բացում է փոքր ձև (անուն, հեռախոս). **գարաժը և ծառայությունը արդեն լրացված են**, ուստի հայտը միշտ հասնում է ճիշտ գարաժին։ Քարտերը կարելի է դասավորել գնով կամ գնահատականով, իսկ «Կարծիքներ» կոճակը ցույց է տալիս վարորդների մեկնաբանությունները։

**Ինչպես են հայտնվում գնահատականները.**
1. Հայտ թողնելուց հետո վարորդը chat-ում ստանում է **անհատական գաղտնի հղում** (`/review/...`)։ Գարաժը այդ հղումը **չի տեսնում** (հակառակ դեպքում կկարողանար գրել կեղծ կարծիք)։
2. Վարորդը հղումով հաստատում է՝ **գնացի՞ք**։ Եթե այո՝ գնահատում է 1-5 աստղով և ցանկության դեպքում գրում կարծիք. եթե ոչ՝ ընտրում է պատճառը (հրապարակային չէ)։
3. Chat-ը նույն դիտարկչում 4 ժամ հետո ցույց է տալիս հիշեցում՝ «Գնացի՞ք, գնահատեք»։

**Կանոններ, որոնք պաշտպանում են վստահությունը**
- Մեկ հայտ՝ մեկ կարծիք։ Նույն հեռախոսից նույն գարաժին՝ 30 օրվա ընթացքում առավելագույնը մեկ «գնացի» կարծիք։
- Վարկանիշը (և դասավորումը «Գնահատականով») հաշվվում է **Bayes-ի ուղղումով**. 1 կարծիքով 5.0-ը չի հաղթում 50 կարծիքով 4.7-ին։ 5-ից քիչ կարծիքի դեպքում քարտը գրում է «(քիչ կարծիք)»։
- Միայն ադմինը կարող է **թաքցնել** կեղծ կամ վիրավորական կարծիք (պարտադիր պատճառով). գարաժը չի կարող ջնջել կամ թաքցնել։ Թաքցվածը չի հաշվվում։
- «Կարծիքներ» բաժինը պանելում. ադմինը տեսնում է ամեն ինչ (նաև «չգնացի»-ի պատճառները), գարաժը՝ միայն իր հրապարակային կարծիքները։
- Հաշվետվությունը ցույց է տալիս **վարորդի հաստատած այցերը** և ⚠ **անհամապատասխանությունը** (գարաժը նշել է «Այցելեց», վարորդը՝ «չգնացի»)։

**Սահմանափակումներ (անկեղծ).**
- Վարորդին հասնում ենք միայն հղումով և նույն դիտարկչի հիշեցումով։ Ով հղումը չպահի կամ դիտարկիչը փոխի, չի գնահատի, ուստի սկզբում կարծիքները քիչ կլինեն։ Լուծում՝ վարորդի Telegram բոտ կամ SMS (դեռ կառուցված չէ)։
- Չկա պաշտպանություն մարդու դեմ, ով գարաժի անունից բազմաթիվ տարբեր հեռախոսներով հայտեր և կարծիքներ գրում է. միակ պաշտպանությունը 30 օրվա կանոնն է, մոդերացիան և հաշվետվության անհամապատասխանության ազդանշանը։
- Դեմոյում նմուշային կարծիքներ չկան (կեղծ կարծիքներ չենք ավելացնում). վարկանիշը երևում է, երբ առաջին վարորդը գնահատի։

## Telegram ծանուցումներ

1. Telegram-ում գտեք **@BotFather** → `/newbot` → տվեք անուն և օգտանուն (վերջանում է `bot`-ով) → ստացեք **token** (`123456:ABC...`)։
2. Render → ձեր ծառայությունը → **Environment** → ավելացրեք `TELEGRAM_BOT_TOKEN` = token-ը → **Save**։ Ծառայությունը ինքը կվերագործարկվի և կգրանցի webhook-ը (Render-ը հասցեն տալիս է ավտոմատ). այլ հոսթինգի դեպքում ավելացրեք `PUBLIC_URL=https://ձեր-հասցեն`։
3. Պանելում «Հայտեր» էջում գլխավոր ադմինը սեղմում է **Միացնել Telegram**, բացում է հղումը և սեղմում **Start**։ Այսուհետ ամեն նոր հայտ գալիս է նրան։
4. Յուրաքանչյուր գարաժ նույնը անում է իր մուտքից («Իմ գարաժը» → **Միացնել Telegram**) կամ ադմինը՝ նրա փոխարեն։ Այդ գարաժը ստանում է միայն իր հայտերը։

Ծանուցումը գալիս է, երբ (ա) հայտը ստեղծվել է արդեն ընտրված գարաժով, կամ (բ) ադմինը նշանակել է հայտը գարաժի։ Հայտը միշտ պահվում է պանելում, նույնիսկ եթե Telegram-ը չաշխատի։

## Փոփոխականներ

| Անուն | Նշանակություն |
|---|---|
| `ADMIN_PASSWORD` | ադմինի գաղտնաբառ (production-ում պարտադիր) |
| `SECRET_KEY` | token-ների ստորագրման բանալի (production-ում պարտադիր) |
| `ANTHROPIC_API_KEY` | AI-ի բանալի. դատարկ՝ պարզ ռեժիմ |
| `ANTHROPIC_MODEL` | մոդելի անուն (լռելյայն՝ `claude-sonnet-5-5`) |
| `AUTOSERVICE_DB` | բազայի ֆայլի ճանապարհ |
| `SEED_SAMPLE` | `1`՝ նմուշային գարաժներ առաջին գործարկման ժամանակ, `0`՝ դատարկ բազա |
| `TELEGRAM_BOT_TOKEN` | Telegram բոտի token (դատարկ՝ ծանուցումներ չկան) |
| `PUBLIC_URL` | կայքի հանրային հասցեն (Render-ում ավտոմատ է՝ `RENDER_EXTERNAL_URL`) |
| `APP_ENV` | `production`՝ առանց գաղտնաբառի սերվերը չի սկսվում |

## Տեղակայում (Docker)

```
docker build -t autoservice .
docker run -d -p 8000:8000 -v autoservice-data:/data --env-file .env autoservice
```

`/data` volume-ը պարտադիր է. այնտեղ է բազան, առանց դրա տվյալները կկորչեն կոնտեյները թարմացնելիս։ Ծառայությունը կարելի է դնել Render, Railway, Fly.io կամ սովորական VPS-ի վրա. կարևոր է միացնել HTTPS (այս հարթակների մեծ մասը դա անում է ինքնուրույն) և persistent disk/volume։

**Backup.** բազան մեկ ֆայլ է (`autoservice.db`). պարբերաբար պատճենեք այն։

## Իրական գարաժի հետ փորձարկման ցուցակ

1. Գործարկեք `SEED_SAMPLE=0`-ով, որպեսզի նմուշային գարաժներ չլինեն։
2. Ադմին պանելում ավելացրեք իրական գարաժը, ծառայությունները, գները, ժամերը։ Ստուգեք տվյալները գարաժի սեփականատիրոջ հետ։
3. Ստուգեք chat-ը տասը իրական վարորդական նկարագրությամբ. ինչ չի գտնվում, ավելացրեք որպես ծառայություն կամ բանալի բառ։
4. Գարաժի աշխատակիցը պետք է օրական մի քանի անգամ բացի «Հայտեր» էջը (ծանուցումներ դեռ չկան)։
5. Հետևեք AI-ի ծախսին Anthropic Console-ում. chat-ը սահմանափակված է 20 հարցում/րոպե մեկ IP-ից։

## Ինչ դեռ չկա

- **Գրանցում ժամին** (սլոթեր). այժմ միայն հայտ է, և գարաժը զանգահարում է վարորդին։
- **SMS ծանուցումներ.** միայն Telegram կա։
- **Գաղտնաբառի վերականգնում ինքնուրույն.** սեփականատերը մոռանալու դեպքում դիմում է գլխավոր ադմինին, որը սահմանում է նոր գաղտնաբառ։
- **Մեկից ավելի սերվեր.** SQLite-ը հարմար է մեկ սերվերի և փոքր ծանրաբեռնվածության համար. աճի դեպքում անցեք PostgreSQL-ի։
- `--proxy-headers`-ը վստահում է `X-Forwarded-For`-ին. եթե սերվերը հասանելի է ուղղակիորեն առանց proxy-ի, IP-ի սահմանափակումը հնարավոր է շրջանցել։

## Անվճար դեմո Render-ում

1. Ստեղծեք GitHub հաշիվ և **նոր private repository**։ Վերբեռնեք այս թղթապանակի ֆայլերը **repository-ի արմատում** (`api.py`, `render.yaml` և մնացածը՝ ոչ թե ենթաթղթապանակում)։ `.gitignore`-ը արդեն կա։
2. render.com → գրանցվեք GitHub-ով (քարտ պետք չէ) → **New → Blueprint** → ընտրեք repository-ն։
3. Render-ը կհարցնի `ADMIN_PASSWORD`. մուտքագրեք երկար գաղտնաբառ։ Սեղմեք **Apply**։
4. 3-5 րոպե հետո կստանաք հասցե՝ `https://ai-auto-service-xxxx.onrender.com`։ Chat՝ `/app`, ադմին՝ `/panel`։

**Ինչ պետք է իմանալ**
- 15 րոպե անգործությունից հետո սերվերը քնում է. հաջորդ բացումը 30-60 վայրկյան է։ **Դեմոյից 2 րոպե առաջ բացեք հղումը հեռախոսից։**
- Ամեն քնելիս/վերագործարկելիս տվյալները վերադառնում են նմուշային վիճակին (ադմինի փոփոխությունները և հայտերը ջնջվում են)։ Դեմոյի համար սա հարմար է, իրական գարաժի համար՝ ոչ (տե՛ս ստորև)։
- AI-ը միացնելու համար Render → Environment → ավելացրեք `ANTHROPIC_API_KEY`։ Օրական սահմանը՝ `AI_DAILY_LIMIT` (100). անցնելիս chat-ը անցնում է պարզ ռեժիմի։ Դեմոյի համար լավ է Anthropic Console-ում սահմանել նաև ծախսի սահման։

**Իրական գարաժի համար** անվճար պլանը չի պիտանի, քանի որ տվյալները չեն պահվում։ Անհրաժեշտ կլինի վճարովի instance persistent disk-ով (հիմա ամսական մի քանի դոլար, ստուգեք render.com/pricing) և `AUTOSERVICE_DB=/data/autoservice.db`, `SEED_SAMPLE=0`։
