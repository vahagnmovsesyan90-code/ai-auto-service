# AI Auto Service

Վարորդը chat-ում նկարագրում է մեքենայի խնդիրը, AI-ը գտնում է ծառայությունը և գարաժները (գնով, ժամերով), իսկ վարորդը կարող է թողնել հայտ։ Գարաժների, գների, ժամերի և հայտերի կառավարումը՝ ադմին պանելում։

## Ֆայլեր

| Ֆայլ | Դերը |
|---|---|
| `data.py` | մոդելներ + նմուշային տվյալներ |
| `db.py` | PostgreSQL բազա (psycopg 3, pool, աղյուսակներ, seed, `python db.py ...`) |
| `testdb.py` | թեստերի համար ժամանակավոր Postgres բազա (ավարտին ջնջվում է) |
| `docker-compose.yml` | տեղական Postgres (`docker compose up -d db`) և, ըստ ցանկության, հավելվածը |
| `queries.py` | ընթերցում/գրառում բազայում |
| `api.py` | FastAPI. հանրային endpoint-ներ, `/app`, `/panel` |
| `admin.py`, `auth.py` | ադմինի API (դերերով), մուտք, rate limit |
| `telegram.py` | Telegram ծանուցումներ և կապ (webhook) |
| `geo.py` | հասցեի որոնում քարտեզում (Nominatim, կանոններով սահմանափակված) |
| `static/leaflet/` | Leaflet 1.9.4 քարտեզի գրադարան (BSD-2), սերվերից է, CDN չկա |
| `chat.py` | AI (Claude + գործիքներ) և պարզ ռեժիմ |
| `chat.html`, `admin.html` | վարորդի chat-ը (քարտեր, «Իմ հայտերը»՝ գնահատում աստղերով), ադմին պանելը |
| `static/ui.css` | ընդհանուր դիզայնը բոլոր վարորդի էջերի համար (գույներ, վերնագիր, կոճակներ, քարտեր, մոդալ, մոբայլի ներքևի ներդիրներ). աղբյուրը՝ «AI Auto Service — նոր դիզայն» canvas-ը |
| `my.html` | «Իմ հայտերը» էջը (`/my`)՝ վարորդի հայտերը և գնահատումը աստղերով. token-ները վարորդի սարքում են, էջավորումը սերվերում (`POST /my-requests/check`՝ `page`, `per_page`) |
| `garages.html`, `garage.html` | գարաժների էջը (`/catalog`՝ իմաստային որոնում նույն AI-ով, ինչ օգնականը, էջավորումը սերվերում) և գարաժի էջը (`/catalog/{id}`՝ ծառայություններ, գներ, ժամեր, կարծիքներ, հայտի ձև) |
| `download.html`, `downloads/`, `webview/` | հավելվածի ներբեռնման էջը (`/download`), պատրաստի փաթեթների պանակը (git-ում չեն) և պատյանների աղբյուրը Android/iOS/Windows/macOS/Linux-ի համար (տես `webview/README.md`)։ Ադմինում՝ «Հավելվածներ» բաժինը |
| `assetlinks.json` | Android App Links (`/.well-known/assetlinks.json`)՝ կայքի հղումները բացվում են հավելվածում |
| `test_api.py` | API-ի, բազայի, ադմինի, հայտերի թեստեր՝ `python test_api.py` |
| `test_ai.py` | AI-ի հանգույցի թեստ կեղծ սերվերով (բանալի պետք չէ)՝ `python test_ai.py` |
| `test_telegram_browser.py` | Telegram-ի կապի և ծանուցումների դիտարկչային թեստ (կեղծ Telegram API-ով)՝ `python test_telegram_browser.py` |
| `test_browser.py` | իրական դիտարկչով թեստ (`pip install playwright && playwright install chromium`)՝ `python test_browser.py` |

## Գործարկում (Docker)

Պրոյեկտն ամբողջությամբ աշխատում է Docker Compose-ով՝ PostgreSQL 17 + հավելված։

```
cp .env.example .env                # լրացրեք ADMIN_PASSWORD, SECRET_KEY, ANTHROPIC_API_KEY (ցանկության դեպքում)
docker compose up -d --build        # dev ռեժիմ. կոդը mount է արված, ֆայլը փոխելիս սերվերը ինքն է վերաբեռնվում
docker compose logs -f app          # լոգեր
docker compose down                 # կանգնեցնել (տվյալները մնում են pgdata volume-ում)
```

- `docker-compose.yml`՝ բազան և հավելվածը, `docker-compose.override.yml`՝ dev հավելումները (bind mount, `--reload`), որոնք `docker compose up`-ը ավտոմատ միացնում է։ Production-ում՝ `docker compose -f docker-compose.yml up -d --build`։
- Բազայի հասցեն `DATABASE_URL`-ն է. compose-ում այն ավտոմատ ցույց է տալիս `db` կոնտեյներին։ Host-ից բազան հասանելի է `127.0.0.1:5433`-ով (user/pass/db՝ `autoservice`)։ Աղյուսակները ստեղծվում են ավտոմատ առաջին գործարկման ժամանակ։
- Թեստեր կոնտեյների մեջ՝ `docker compose run --rm app python test_api.py` և `... test_ai.py` (ամեն թեստ իր ժամանակավոր բազան է ստեղծում և ջնջում)։ Դիտարկչային թեստերը (`test_browser.py`, `test_telegram_browser.py`) պահանջում են playwright, ուստի աշխատում են host-ից՝ `.venv`-ով, նույն Postgres-ի վրա։

**Առանց Docker-ի** (եթե Postgres-ը ուրիշ տեղ է)՝ `pip install -r requirements.txt`, `export DATABASE_URL=postgresql://user:pass@host:5432/dbname`, `uvicorn api:app --reload`։

**Հին SQLite բազայից անցնելիս.** `python db.py import-sqlite autoservice.db` տեղափոխում է բոլոր տվյալները (գարաժներ, գներ, ժամեր, հայտեր, կարծիքներ, մուտքեր) դատարկ Postgres-ի մեջ։

- Chat՝ http://127.0.0.1:8000/app
- Ադմին՝ http://127.0.0.1:8000/panel (dev-ում գաղտնաբառը `admin`, եթե `ADMIN_PASSWORD` չեք նշել)
- API-ի փաստաթղթեր՝ http://127.0.0.1:8000/docs

## Դերեր. ինչպես է յուրաքանչյուր գարաժը տեսնում միայն իր հայտերը

- **Գլխավոր ադմին** (`ADMIN_PASSWORD`). մուտքանունը թողնում է դատարկ։ Տեսնում և կառավարում է ամեն ինչ։
- **Գարաժի սեփականատեր.** գլխավոր ադմինը «Գարաժներ» → գարաժ → «Գարաժի մուտք» բաժնում սահմանում է մուտքանուն և գաղտնաբառ։ Սեփականատերը մտնում է նույն `/panel` էջով և տեսնում է **միայն իր** հայտերը, գները, ժամերը. նա չի կարող դիպչել այլ գարաժին, կատալոգին կամ ջնջել գարաժ։
- **Հայտի ուղղորդում.** եթե վարորդը հայտի ձևում ընտրել է գարաժ, հայտը գնում է հենց այդ գարաժին։ Առանց ընտրության հայտերը տեսնում է միայն գլխավոր ադմինը և նշանակում է գարաժի («Հայտեր» էջում)։

## Հայտի փուլեր և հաշվետվություն

Յուրաքանչյուր հայտ ունի փուլ, որը գարաժը թարմացնում է «Հայտեր» էջում.

**Նոր → Զանգահարվել է → (Չպատասխանեց) → Ժամ պայմանավորվեց → Այցելեց**, կամ **Հրաժարվեց** (պարտադիր պատճառով՝ թանկ է, հեռու է, գնաց այլ գարաժ, ժամը չհամապատասխանեց, այլևս պետք չէ, այլ)։

«Հաշվետվություն» էջը (ամսական, Երևանի ժամանակով) ցույց է տալիս.
- քանի հայտ եկավ, քանի տոկոսի հետ կապվեցին (**Արձագանքվել է**), քանիսի հետ ժամ պայմանավորվեցին, քանիսն **այցելեցին**,
- **արձագանքման միջնային ժամանակը** (հայտի ստեղծումից մինչև առաջին փուլի փոփոխությունը),
- հրաժարումների պատճառները։

Ադմինը տեսնում է բոլոր գարաժները և «Նշանակված չէ» հայտերը, գարաժը՝ միայն իրենը։

**Սահմանափակումներ.** վիճակները **ընթացիկն են** (պատմություն չենք պահում), ուստի «ժամ պայմանավորվեց»-ի տոկոսը հաշվում է հիմա «ժամ»/«այցելեց» փուլում գտնվողներին։ «Այցելեց» փուլը լրացնում է հենց գարաժը, և դուք չեք կարող ստուգել դրա ճշտությունը (հաճախորդի հաստատում դեռ չկա)։ Արձագանքման ժամանակը ճշգրիտ է միայն գարաժի պանելը օգտագործելու դեպքում։

## Հայերեն տառեր

Chat-ի մուտքի դաշտը հուշում է գրել հայերեն տառերով (placeholder և ողջույն)։ Եթե վարորդը սկսում է գրել լատինատառ կամ ռուսերեն (տեքստի մեծ մասը ոչ հայերեն տառեր է), մուտքի դաշտի վերևում երևում է հուշում։ **Ուղարկելը չի արգելվում**, որովհետև մակնիշները (BMW, Toyota) լատինատառ են. «BMW արգելակ» հուշում չի առաջացնում։ Եթե պարզ ռեժիմը գրածը չի հասկանում և այն հիմնականում ոչ հայերեն է, բոտը կրկնում է հուշումը. AI ռեժիմում Claude-ը փորձում է հասկանալ և քաղաքավարի խնդրում է հաջորդիվ գրել հայերեն տառերով։

## Հավելված հեռախոսում և համակարգչում

Կայքը ունի **բնիկ պատյաններ** Android-ի, iPhone/iPad-ի, Windows-ի, macOS-ի և Linux-ի համար (`webview/`, նույն կառուցվածքով, ինչ TutorVoice-ինը). հավելվածը բացում է նույն կայքը իր պատուհանում, առանց բրաուզերի, պահում է մուտքը, աշխատում է offline էջով և համակարգի ծանուցումներով։
- **Ներբեռնման էջ**՝ `/download` (վերնագրի «Հավելված» կետը բոլոր էջերում, ադմինում՝ «Հավելվածներ» բաժինը)։ Էջը ճանաչում է սարքը և իր քարտը դնում վերևում. փաթեթ ունեցողին տալիս է ֆայլը (չափով, տարբերակով), չունեցողին (iPhone, մինչև App Store)՝ «Ավելացնել գլխավոր էկրանին» ճանապարհը։
- **Փաթեթները** `downloads/` պանակում են (`webview/bin/publish.sh`), անունը խիստ է՝ `aiauto-<տարբերակ>-<հարթակ>[-<ճարտ.>].<ext>`։ Ցանկը՝ `GET /api/downloads`, ֆայլը՝ `/downloads/<անուն>`։ Docker-ում պանակը volume է (`./downloads:/app/downloads`)։
- **Android**-ի APK-ն ստորագրված է (`webview/android/keystore.properties` + `.jks`, git-ում չեն՝ պահեք backup), App Links-ի համար `/.well-known/assetlinks.json`-ը տրվում է `assetlinks.json`-ից։ **Windows**-ի ինստալյատորը ստորագրված չէ (SmartScreen-ի զգուշացում)։ **macOS** `.dmg`-ն և **iOS**-ը կառուցվում են միայն Mac-ի վրա (Apple Developer հաշիվ). խանութների հղումները՝ `APP_STORE_URL`, `PLAY_STORE_URL`։
- Մանրամասն՝ `webview/README.md`։

## Գարաժի քարտեր և գնահատականներ

**Chat-ում** գարաժները երևում են քարտերով՝ գին, հասցե, բաց է/փակ է, **գնահատական** և **«Թողնել հայտ»** կոճակ։ Կոճակը բացում է փոքր ձև (անուն, հեռախոս). **գարաժը և ծառայությունը արդեն լրացված են**, ուստի հայտը միշտ հասնում է ճիշտ գարաժին։ Քարտերը կարելի է դասավորել գնով կամ գնահատականով, իսկ «Կարծիքներ» կոճակը ցույց է տալիս վարորդների մեկնաբանությունները։

**Ինչպես են հայտնվում գնահատականները.**
1. Հայտ թողնելուց հետո վարորդի սարքում պահվում է **անհատական գաղտնի token**, իսկ գնահատումը արվում է «Իմ հայտերը» էջում (`/my`)՝ աստղերով։ Գարաժը այդ token-ը **չի տեսնում** (հակառակ դեպքում կկարողանար գրել կեղծ կարծիք)։
2. Վարորդը հղումով հաստատում է՝ **գնացի՞ք**։ Եթե այո՝ գնահատում է 1-5 աստղով և ցանկության դեպքում գրում կարծիք. եթե ոչ՝ ընտրում է պատճառը (հրապարակային չէ)։
3. **Հղումը չի կորչում.** Chat-ի խոսակցությունը (քարտերը և հայտի հաստատումը՝ հղումով) պահվում է վարորդի սարքում մինչև 7 օր, այնպես որ հավելվածը փակելով և նորից բացելով ոչինչ չի ջնջվում։ Բացի այդ, վերևում միշտ կա **«Իմ հայտերը»** կոճակ. այնտեղ երևում են բոլոր հայտերը (մինչև 90 օր) «Գնահատել» հղումով, իսկ գնահատվածները՝ «✓ Գնահատված»։ «Նոր խոսակցություն» կոճակը մաքրում է միայն չատը, ոչ «Իմ հայտերը»։
4. **Երկրորդ պահոց.** եթե դիտարկիչը արգելում է տվյալների պահպանումը (private ռեժիմ և այլն), chat-ը նախազգուշացնում է և պահում է գնահատման հղումը **հասցեագոտում** (`#h=...`), ուստի refresh-ից հետո «Իմ հայտերը» դարձյալ երևում է։ Եթե էջը թարմացվել է պատասխանի սպասման ժամանակ, չստացված հարցը վերադառնում է մուտքի դաշտ։
5. **Անվավեր հղումները չեն երևում «Իմ հայտերը» ցուցակում.** chat-ը ամեն բացելիս և ամեն ցուցակ բացելիս հարցնում է սերվերին (`POST /my-requests/check`, մեկ հարցումով). եթե հայտը սերվերում այլևս չկա (օր.՝ անվճար հոսթինգի վերագործարկումից հետո), այն հանվում է ցուցակից։ Ցանցի անկման դեպքում ոչինչ չի ջնջվում։ 
6. **Տարբերակ.** էջի ներքևում գրված է տարբերակը (օր.՝ `v2.3`), իսկ `GET /` պատասխանում կա `version`։ Թարմացումից հետո ստուգեք, որ ձեր դիտարկչում երևում է նոր համարը. եթե ոչ, դուք դեռ տեսնում եք հին էջը (սեղմեք Ctrl+F5)։ HTML էջերը այժմ ուղարկվում են `Cache-Control: no-cache`-ով, որպեսզի թարմացումից հետո հին տարբերակը չմնա քեշում։
7. Chat-ը նույն դիտարկչում 4 ժամ հետո ցույց է տալիս նաև հիշեցում՝ «Գնացի՞ք, գնահատեք»։

**Կանոններ, որոնք պաշտպանում են վստահությունը**
- Մեկ հայտ՝ մեկ կարծիք։ Նույն հեռախոսից նույն գարաժին՝ 30 օրվա ընթացքում առավելագույնը մեկ «գնացի» կարծիք։
- Վարկանիշը (և դասավորումը «Գնահատականով») հաշվվում է **Bayes-ի ուղղումով**. 1 կարծիքով 5.0-ը չի հաղթում 50 կարծիքով 4.7-ին։ 5-ից քիչ կարծիքի դեպքում քարտը գրում է «(քիչ կարծիք)»։
- Միայն ադմինը կարող է **թաքցնել** կեղծ կամ վիրավորական կարծիք (պարտադիր պատճառով). գարաժը չի կարող ջնջել կամ թաքցնել։ Թաքցվածը չի հաշվվում։
- «Կարծիքներ» բաժինը պանելում. ադմինը տեսնում է ամեն ինչ (նաև «չգնացի»-ի պատճառները), գարաժը՝ միայն իր հրապարակային կարծիքները։
- Հաշվետվությունը ցույց է տալիս **վարորդի հաստատած այցերը** և ⚠ **անհամապատասխանությունը** (գարաժը նշել է «Այցելեց», վարորդը՝ «չգնացի»)։

**Սահմանափակումներ (անկեղծ).**
- **Տվյալները պահվում են վարորդի սարքում (դիտարկչում).** եթե վարորդը մաքրի դիտարկչի տվյալները, անցնի այլ սարքի կամ դիտարկչի, «Իմ հայտերը» և հղումը չեն երևա։ **iPhone-ում տեղադրված հավելվածը (Home Screen) և Safari-ն ունեն առանձին պահոց**, ուստի Safari-ով թողած հայտը չի երևա տեղադրված հավելվածում. վարորդը պետք է գնահատի նույն տեղից, որտեղ հայտ է թողել։ Համարով ինքնուրույն վերականգնելը հնարավոր չէ առանց SMS հաստատման (այլապես ցանկացած մարդ կարող էր ուրիշի հայտով կեղծ կարծիք գրել)։
- **Անվճար Render-ում սերվերը քնելիս հայտերը ջնջվում են**, և այդ դեպքում հին գնահատման հղումը ցույց կտա «Հղումը անվավեր է»։ Իրական փորձարկման համար պետք է վճարովի plan persistent disk-ով։
- Վարորդին հասնում ենք միայն հղումով և նույն դիտարկչի հիշեցումով։ Ով հղումը չպահի կամ դիտարկիչը փոխի, չի գնահատի, ուստի սկզբում կարծիքները քիչ կլինեն։ Լուծում՝ վարորդի Telegram բոտ կամ SMS (դեռ կառուցված չէ)։
- Չկա պաշտպանություն մարդու դեմ, ով գարաժի անունից բազմաթիվ տարբեր հեռախոսներով հայտեր և կարծիքներ գրում է. միակ պաշտպանությունը 30 օրվա կանոնն է, մոդերացիան և հաշվետվության անհամապատասխանության ազդանշանը։
- Դեմոյում նմուշային կարծիքներ չկան (կեղծ կարծիքներ չենք ավելացնում). վարկանիշը երևում է, երբ առաջին վարորդը գնահատի։

## Գարաժի տեղը և «Երթուղի» կոճակը

Գարաժի սեփականատերը (կամ ադմինը) պանելի «Գարաժներ» բաժնում ունի «Գարաժի տեղը քարտեզում» տուփ։ Կետը կարելի է դնել երեք ձևով.
1. **«Ես գարաժում եմ»**՝ հեռախոսի/համակարգչի տեղորոշումը (ցույց է տալիս ճշտությունը, օր.՝ ±25 մ),
2. **հասցեի դաշտ + «Գտնել հասցեով»**՝ գտնում է մոտավոր կետը,
3. **սեղմել քարտեզին** և քաշել կարմիր կետը ճիշտ մուտքի վրա։

Ոչ մի ձև ինքնուրույն չի պահպանում. միշտ երևում է քարտեզին, և կետը հաստատվում է **«Պահպանել կետը»** կոճակով։
Եթե փոխեք հասցեն և սեղմեք «Պահպանել», **հին կետը հանվում է** (որպեսզի վարորդներին հին տեղ չուղարկենք), մինչև նորը հաստատվի։
Chat-ի քարտում **«Երթուղի»** կոճակը երևում է միայն հաստատված կետ ունեցող գարաժի համար. այն բացում է Google Maps / Yandex Maps / Waze՝ կոորդինատներով, իսկ **սկիզբը վարորդի ընթացիկ տեղն է**՝ քարտեզի հավելվածն ինքն է որոշում. մենք վարորդի տեղը չենք տեսնում և չենք պահում։

**Կարևոր սահմանափակումներ**
- Հասցեի որոնումը օգտագործում է անվճար **Nominatim**-ը ([կանոններ](https://operations.osmfoundation.org/policies/nominatim/)). սահմանը **ամբողջ հավելվածի համար** է՝ առավելագույնը 1 հարցում/վայրկյան, պարտադիր է մեր կոնտակտով User-Agent (`NOMINATIM_CONTACT`), ավտոլրացում և զանգվածային որոնում արգելված են։ Կոդը կատարում է սրանք (կոճակով, 1/վրկ, քեշ), բայց կանոնները կարող են փոխվել. շատ գարաժների դեպքում անցեք վճարովի geocoder-ի։ Հայկական հասցեների ծածկույթը չի ստուգվել. եթե չգտնի, կետը դրեք քարտեզին ձեռքով։
- Քարտեզի նկարները բեռնվում են OpenStreetMap-ի հանրային սերվերից (© OpenStreetMap contributors). դա նախատեսված չէ մեծ ծանրաբեռնվածության համար։
- «Երթուղի» հղումների ձևաչափերը (Google/Yandex/Waze) **չեն փորձարկվել իրական Android/iPhone-ներում** (Yandex-ի՝ «ընթացիկ տեղից» ձևը հատկապես). փորձեք դրանք ձեր հեռախոսում։

## Telegram ծանուցումներ

1. Telegram-ում գտեք **@BotFather** → `/newbot` → տվեք անուն և օգտանուն (վերջանում է `bot`-ով) → ստացեք **token** (`123456:ABC...`)։
2. Render → ձեր ծառայությունը → **Environment** → ավելացրեք `TELEGRAM_BOT_TOKEN` = token-ը → **Save**։ Ծառայությունը ինքը կվերագործարկվի և կգրանցի webhook-ը (Render-ը հասցեն տալիս է ավտոմատ). այլ հոսթինգի դեպքում ավելացրեք `PUBLIC_URL=https://ձեր-հասցեն`։
3. Պանելում «Հայտեր» էջում գլխավոր ադմինը սեղմում է **Միացնել Telegram**, բացում է հղումը և սեղմում **Start**։ Այսուհետ ամեն նոր հայտ գալիս է նրան։
4. Յուրաքանչյուր գարաժ նույնը անում է իր մուտքից («Իմ գարաժը» → **Միացնել Telegram**) կամ ադմինը՝ նրա փոխարեն։ Այդ գարաժը ստանում է միայն իր հայտերը։

Ծանուցումը գալիս է, երբ (ա) հայտը ստեղծվել է արդեն ընտրված գարաժով, կամ (բ) ադմինը նշանակել է հայտը գարաժի։ Հայտը միշտ պահվում է պանելում, նույնիսկ եթե Telegram-ը չաշխատի։

## Փոփոխականներ

| Անուն | Նշանակություն |
|---|---|
| `ADMIN_PASSWORD` | ադմինի գաղտնաբառ (production-ում պարտադիր) |
| `SECRET_KEY` | token-ների ստորագրման բանալի (production-ում պարտադիր) |
| `ANTHROPIC_API_KEY` | AI-ի բանալի. դատարկ՝ պարզ ռեժիմ |
| `ANTHROPIC_MODEL` | մոդելի անուն (լռելյայն՝ `claude-sonnet-5-5`) |
| `DATABASE_URL` | PostgreSQL-ի հասցեն (compose-ում՝ ավտոմատ `db` կոնտեյներին) |
| `SEED_SAMPLE` | `1`՝ նմուշային գարաժներ առաջին գործարկման ժամանակ, `0`՝ դատարկ բազա |
| `TELEGRAM_BOT_TOKEN` | Telegram բոտի token (դատարկ՝ ծանուցումներ չկան) |
| `NOMINATIM_CONTACT` | **ձեր էլ. փոստը**՝ հասցեի որոնման User-Agent-ի համար (OSM-ի կանոն. լրացրեք) |
| `PUBLIC_URL` | կայքի հանրային հասցեն (Render-ում ավտոմատ է՝ `RENDER_EXTERNAL_URL`) |
| `APP_ENV` | `production`՝ առանց գաղտնաբառի սերվերը չի սկսվում |
| `AI_DAILY_LIMIT` | AI հարցումների օրական սահման (լռելյայն 100). անցնելիս՝ պարզ ռեժիմ |
| `APP_STORE_URL`, `PLAY_STORE_URL` | խանութների հղումները `/download` էջի համար (դատարկ՝ միայն ֆայլերը) |
| `DOWNLOADS_DIR` | փաթեթների պանակը (լռելյայն՝ `downloads/`) |

## Տեղակայում

Production-ում՝ `docker compose -f docker-compose.yml up -d --build` (տես վերևում). HTTPS-ը տալիս է դիմացի proxy-ն (nginx/Caddy) `aiauto.am` դոմենով։ Տվյալները `pgdata` volume-ում են, փաթեթները՝ `./downloads`-ում։

**Backup.** `docker compose exec db pg_dump -U autoservice autoservice > backup.sql` (վերականգնում՝ `psql`-ով)։

## Իրական գարաժի հետ փորձարկման ցուցակ

1. Գործարկեք `SEED_SAMPLE=0`-ով, որպեսզի նմուշային գարաժներ չլինեն։
2. Ադմին պանելում ավելացրեք իրական գարաժը, ծառայությունները, գները, ժամերը։ Ստուգեք տվյալները գարաժի սեփականատիրոջ հետ։
3. Ստուգեք chat-ը տասը իրական վարորդական նկարագրությամբ. ինչ չի գտնվում, ավելացրեք որպես ծառայություն կամ բանալի բառ։
4. Գարաժի աշխատակիցը պետք է օրական մի քանի անգամ բացի «Հայտեր» էջը (ծանուցումներ դեռ չկան)։
5. Հետևեք AI-ի ծախսին Anthropic Console-ում. chat-ը սահմանափակված է 20 հարցում/րոպե մեկ IP-ից։

## Ինչ դեռ չկա

- **Գրանցում ժամին** (սլոթեր). այժմ միայն հայտ է, և գարաժը զանգահարում է վարորդին։
- **SMS ծանուցումներ.** միայն Telegram կա։
- **Գաղտնաբառի վերականգնում ինքնուրույն.** սեփականատերը մոռանալու դեպքում դիմում է գլխավոր ադմինին, որը սահմանում է նոր գաղտնաբառ։
- `--proxy-headers`-ը վստահում է `X-Forwarded-For`-ին. եթե սերվերը հասանելի է ուղղակիորեն առանց proxy-ի, IP-ի սահմանափակումը հնարավոր է շրջանցել։

## Անվճար դեմո Render-ում

1. Ստեղծեք GitHub հաշիվ և **նոր private repository**։ Վերբեռնեք այս թղթապանակի ֆայլերը **repository-ի արմատում** (`api.py`, `render.yaml` և մնացածը՝ ոչ թե ենթաթղթապանակում)։ `.gitignore`-ը արդեն կա։
2. render.com → գրանցվեք GitHub-ով (քարտ պետք չէ) → **New → Blueprint** → ընտրեք repository-ն։
3. Render-ը կհարցնի `ADMIN_PASSWORD`. մուտքագրեք երկար գաղտնաբառ։ Սեղմեք **Apply**։
4. 3-5 րոպե հետո կստանաք հասցե՝ `https://ai-auto-service-xxxx.onrender.com`։ Chat՝ `/app`, ադմին՝ `/panel`։

**Ինչ պետք է իմանալ**
- 15 րոպե անգործությունից հետո սերվերը քնում է. հաջորդ բացումը 30-60 վայրկյան է։ **Դեմոյից 2 րոպե առաջ բացեք հղումը հեռախոսից։**
- Ամեն քնելիս/վերագործարկելիս տվյալները վերադառնում են նմուշային վիճակին (ադմինի փոփոխությունները և հայտերը ջնջվում են)։ Դեմոյի համար սա հարմար է, իրական գարաժի համար՝ ոչ (տե՛ս ստորև)։
- AI-ը միացնելու համար Render → Environment → ավելացրեք `ANTHROPIC_API_KEY`։ Օրական սահմանը՝ `AI_DAILY_LIMIT` (100). անցնելիս chat-ը անցնում է պարզ ռեժիմի։ Դեմոյի համար լավ է Anthropic Console-ում սահմանել նաև ծախսի սահման։

**Իրական գարաժի համար** անվճար պլանը չի պիտանի, քանի որ տվյալները չեն պահվում։ Անհրաժեշտ կլինի վճարովի instance persistent disk-ով (հիմա ամսական մի քանի դոլար, ստուգեք render.com/pricing) և Render Postgres (`DATABASE_URL`), `SEED_SAMPLE=0`։
